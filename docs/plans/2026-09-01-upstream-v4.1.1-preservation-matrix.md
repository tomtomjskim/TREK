> `v4.1.1^{}` `33a33e7b1d113f0742ac609305cc549a4806d31b`

이 문서는 conflict 파일 목록이 아니라 사용자·데이터·보안 동작의 보존 원장이다.
Git이 모든 conflict marker 제거를 강제해도 semantic fork behavior는 조용히 사라질 수 있다.
따라서 각 행은 새 v4 owner module과 재현 테스트가 GREEN이 될 때만 완료한다.

## Status vocabulary

| 상태       | 의미                                                                 |
| ---------- | -------------------------------------------------------------------- |
| `PENDING`  | 아직 RED/GREEN 증거 없음                                             |
| `RED`      | 새 owner path에서 보존 test가 기대한 이유로 실패                     |
| `GREEN`    | focused test가 통과했지만 전체 gate 전                               |
| `VERIFIED` | focused + broader gate + review가 모두 통과                          |
| `RETIRED`  | upstream 동등성이 positive/negative test로 증명되어 local patch 제거 |
| `BLOCKED`  | 구체적인 외부 결정 또는 데이터 fixture가 필요; 근거 기록 필수        |

`HIGH` 행은 `VERIFIED` 또는 근거가 있는 `RETIRED`가 아니면 release candidate를 만들 수 없다.

## Per-lane handoff template

Every worker prompt and evidence entry must fill all fields:

```text
Base SHA:
Worktree/branch:
Preservation IDs:
Owned files:
Forbidden files:
Expected RED command and assertion:
Focused GREEN command:
Broader regression command:
No secret/production data rule:
No commit/push/merge/deploy rule:
Concurrent-edit rule: not alone; do not revert other edits
Handoff: changed files, RED, GREEN, warnings, unresolved risks
```

The root integrator rejects handoffs that say only “tests pass,” omit the actual command/result, or
change files outside ownership without prior coordination.

## Release completion rule

The branch is not an integration candidate until:

- every HIGH row is `VERIFIED` or explicitly `RETIRED` with equivalence evidence;
- no conflict entry or legacy service revival remains;
- every DB/auth/privacy/provider negative matrix cell is evidenced;
- `FORK_MIGRATION_IDS` exact-set/once assertions, every anonymous response section's exact DTO/query
  allowlist, disabled-flag no-query, cross-share-flag no-leak and revoked-token lifecycle evidence are
  fresh;
- storage/plugin backup manifest checksums and staged restore, including object R/W state and
  code/image identity, are successful;
- focused and full repository gates are fresh against the final tree;
- browser screenshots and network/console artifacts bind to the final SHA;
- rollback restore rehearsal is successful;
- the evidence document's current-state declaration still distinguishes local candidate from runtime.
