# TREK v4.2.0 Fork Main Landing Design

## Goal

공식 `liketrek/TREK` v4.2.0을 포크의 기존 이력과 기능을 보존한 채 `main`에
흡수하고 운영에 배포한다. 포크 기능은 다음 공식 버전 동기화 때 기능 단위로
검토·비활성화·제거할 수 있어야 하며, 지도 기본 동작은 API key가 필요 없는
OpenFreeMap을 유지한다.

## Decision

후보 브랜치의 공식 v4.2.0 merge parent와 포크 commit 이력을 그대로 보존하고,
검증된 후보를 포크 `main`으로 fast-forward한다. 선택 기능은 단일 addon id를
REST/MCP/desktop/mobile/admin UI가 함께 사용하도록 한다. 보안·개인정보·동시성·
데이터 정합성 수정은 사용자가 끌 수 있는 기능이 아니므로 runtime toggle을 붙이지
않고, manifest에 소유 경계와 upstream parity가 생겼을 때의 제거 조건을 기록한다.

## Extension classes

| Class | Runtime behavior | Removal behavior |
| --- | --- | --- |
| Optional product addon | addon off 시 서버는 인증 전에 404, 모든 UI entry/panel은 숨김 | domain module, client entry, tests를 manifest 단위로 제거 |
| Provider/config adapter | 설정이 없거나 비활성일 때 외부 호출 없이 keyless fallback | adapter와 config wiring만 제거 |
| Correctness/security invariant | 항상 활성 | upstream 동등 동작과 회귀 테스트를 확인한 뒤 patch/test를 함께 retirement |
| Instance-only operation | 저장소 기본값을 바꾸지 않고 host-local override로 적용 | override image/config만 되돌림 |

## Addon contract

- Vacay: `ADDON_IDS.VACAY`가 controller, MCP/RPC, `/vacay` route를 함께 제어한다.
- Packing: `ADDON_IDS.PACKING`이 packing, todo/list, admin template REST와 plugin RPC,
  trip bundle/public-share projection, trip copy contributor, todo reminder job,
  desktop/mobile planner/share/admin UI와 trip hydration을 함께 제어한다.
- disabled REST 응답은 공통 `AddonGuard` 계약인 404를 사용한다. 같은 guard를
  첫 `APP_GUARD`로 등록해 `GlobalAuthGuard`·MFA policy와 route-level `JwtAuthGuard`보다
  먼저 실행한다. route guard는 request-local marker를 재사용해 addon lookup을
  중복하지 않으며, 기능 존재 여부와 인증·MFA 상태에 따라 다른 surface가
  생기지 않게 한다.
- DB table과 migration ledger는 addon off 때 삭제하지 않는다. runtime disable과
  schema retirement는 별도 수명주기이며, 후자는 명시적 migration/backup이 있어야 한다.

## Upstream conflict boundary

- 공식 v4.2.0 peeled commit은 후보 merge의 parent로 유지한다.
- fork extension manifest가 lane, owner module, toggle, shared/core seam, tests,
  retirement signal을 한 곳에 고정한다.
- Trips core에서 사용하지 않는 Vacay 의존성은 제거한다. 선택 addon을 core
  constructor에 필수 주입하지 않는다.
- plugin으로 옮길 수 없는 auth/data-atomic 기능은 억지로 plugin화하지 않는다.
  대신 domain module, 공통 gate, contract test를 유지한다.

## OpenFreeMap contract

`client/src/utils/tileUrl.ts`와 `VectorBasemap`의 OpenFreeMap fallback을 유지한다.
CARTO key가 없거나 공백이어도 OpenFreeMap URL을 반환해야 하며, 이번 배포에서
CARTO key를 추가하거나 CARTO를 기본값으로 바꾸지 않는다.

## Migration and rollback

분류는 `full_gate_required`, rollback class는 `data_migration`이다. 공식 schema
200..205와 fork migration ledger는 feature toggle과 무관하게 적용된다. 런타임에서
생성한 online backup은 포맷·복원 리허설 증거일 뿐 DB와 uploads/plugin state의
단일 logical point를 보장하지 않는다. 배포 직전에 현재 v3.4.1 서비스를
정지하고 SQLite, uploads, plugin state를 하나의 owner-only checksum snapshot으로
묶은 뒤, 사본을 v4.2 후보 이미지로 migration/restart/integrity 리허설한다.
v4.2 write 뒤 v3.4.1 image-only rollback은 금지하며, 구 이미지와 배포 직전
write-stopped logical-point snapshot을 함께 복원한다. 일반 HTTP, WebSocket, MCP,
plugin 및 cron 작업을 막고 진행 중 write를 drain하는 process-wide restore quiescence와
crash journal/recovery를 구현했지만, 배포 rollback은 더 단순하고 검증 가능한 정지 시점
snapshot 경로를 계속 사용한다. 사용자가 제외한 encryption-key 동일성 증명은 gate에
포함하지 않지만, self-contained backup의 key 파일은 노출 없이 보존한다.

## Landing gate

1. addon-off server/client negative tests와 public/bundle/plugin no-query·no-side-effect tests
2. changed-path lint/typecheck와 full shared/server/client suites
3. production build 및 immutable native ARM64 image smoke
4. write-stopped full-state snapshot, checksum, restore/migration rehearsal
5. 포크 `main` push, Compose image-only diff, app-only cutover
6. local/public health, exact version, schema/fork ledger, OpenFreeMap fallback 확인
7. 배포 증거와 rollback pair 기록
