## Review-driven corrections

Independent conflict reviews initially returned four material findings, all reproduced before the
fixes:

1. `delete_packing_bag` reported success and broadcast for a missing bag.
2. Packing accepted negative/fractional weights and fractional or unbounded quantities.
3. A public Journey photo without `taken_at` could be ordered by a private/skeleton entry date.
4. Some Memories mutations and sync paths bypassed the Journey-addon gate or called the provider
   before rejecting the request.

Regression tests were added first. The fixes are narrow: missing-bag result checks, shared/MCP
numeric schemas plus service normalization, a public-only gallery order fragment, and service-level
addon preflight before mutation/provider access. The private Journey gallery order and legacy
packing response parsing remain unchanged.

The packing REST response now includes server-computed bag and unassigned totals. MCP/plugin list
shapes remain backward-compatible and therefore do not yet expose the unassigned aggregate; a
future additive/versioned contract is preferable to breaking existing plugin consumers.

The follow-up client review added the following focused preservation contracts. Public share map
projection retains valid latitude/longitude `0` values and excludes non-finite or out-of-range
coordinates; place notes remain the shared place note rather than a personal note. CARTO keys are
trimmed before URL binding, and blank/whitespace-only values select the keyless fallback. Audit
detail output redacts secret-like fields. The mobile sheet keeps topmost Escape handling, focus
restoration, and body fixed-scroll locking. On coarse-pointer iPad input, long-press drag remains
available through the touch bridge while native HTML drag is disabled; planner controls expose a
real 44×44 hit target. Vacay deletion is a successful partial operation when the follow-up stats
refresh fails, with the failure observable for diagnostics. Mobile packing uses the same concurrency
and request semantics as desktop. E2E fixtures now enable the required enrichment flags, dismiss
and assert absence of notices before map probes, and clean created state in `finally` blocks so
each test is independently rerunnable.

## CARTO production diagnosis

The deployed v4.2.0 container and migrated database were checked read-only without returning any
credential value:

- `settings` contains zero `carto_api_key` rows;
- `app_settings` contains zero `default_user_setting_carto_api_key` rows;
- the container has no non-empty `CARTO_API_KEY` environment variable;
- no user or instance-default map template points at `basemaps.cartocdn.com`.

Therefore the prior plan-tab watermark was not evidence of an expired bound key. No CARTO key was
bound to TREK at cutover time; CARTO account registration and saving the issued key into TREK are
separate steps. v4.2.0 now selects OpenFreeMap when no key is present, including the Plan map. If
CARTO is deliberately selected later, the key must be saved as a user or instance default and
validated against CARTO. The key itself was neither printed nor written to this ledger.

## Rollback status and residual risks

After a v4.2 database migration, rollback must pair the previous image with the same-logical-point
pre-v4.2 database and uploads snapshot. A code-only rollback is unsafe because the new
`plugin_actions.scope` default can make instance actions visible as user actions to older code.
This deployment retains that exact pair and rehearsed it: image
`sha256:97a4312f262b53c36bc3364ba62ae84282782003db7b68b59ebc60f37c02bd07` plus the archives named
above. The instance had zero installed plugins and no external plugin/storage state at cutover.

Remaining non-blocking risks:

- Both the prior and new image required Docker's timeout kill during rehearsal/stop (exit 137,
  `OOMKilled=false`). Stopped-point and post-kill SQLite checks were `ok`, but graceful container
  shutdown latency should be diagnosed separately.
- No authenticated production browser session was used for the Plan tab. The exact deployed source
  passed isolated authenticated Playwright coverage, and public/local app version binding confirms
  the running image.
- Host WebKit remains limited by the missing `libwoff2dec.so.1.0.2`; Chromium and the earlier
  matching-image WebKit replacement evidence are retained.
- Production audit remains high 0/critical 0/moderate 3/low 1; no dependency auto-fix was mixed
  into the release.
- The configured shared Prettier gate retains its pre-existing baseline failures; no mass formatting
  rewrite was mixed into the upstream merge.
- Upstream's mutated `plugin-sdk-v1.7.0` tag and unchanged SDK package version remain upstream
  provenance concerns, not blockers for the deployed core image.
