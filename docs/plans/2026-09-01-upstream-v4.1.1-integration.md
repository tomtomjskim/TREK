## Execution rules

- Start each task by confirming the branch and clean/expected status. Stop on unrelated user edits.
- Subagents own disjoint files. They are not alone in the codebase and must not revert other edits.
- Workers do not commit, merge, push or deploy. The root integrator alone stages and creates local
  checkpoint commits after reviews.
- No production `.env`, token, signing key, original DB or sensitive log is read or copied.
- A test must fail for the expected missing behavior before implementation. Record the assertion and
  failure, not only the exit code.
- Never resolve a directory with blanket `ours`/`theirs`. Never revive deleted legacy services.
- Update the evidence ledger immediately after each fresh command.
- If a preservation contract conflicts with intentional upstream product behavior, mark it `BLOCKED`
  and ask TOM; do not silently choose one.
- Task 0 commands run on the current fork. Paths and package scripts in Tasks 2–9 are the **post-merge
  v4.1.1 target contract**: they were checked with `git show v4.1.1^{}:<path>`, not against the
  pre-merge worktree. Do not classify a target-only path or script as missing before Task 1.
- Every path introduced by the target tag must exist after Task 1. Every genuinely new fork file is
  labelled `Create` below. An unexpected absence after the merge is a blocker, not a reason to invent
  a replacement path.
